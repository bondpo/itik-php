# 国际化与百度翻译

## 首次部署

1. 在项目根目录执行 `php database/init_i18n.php`。脚本按当前数据库表前缀创建三张独立表，并幂等注入“国际化管理”菜单，不修改原有业务字段。
2. 退出后台后重新登录，为相关管理员分配配置、查看译文、修订发布、重新翻译权限。
3. 打开“国际化管理 → 百度翻译配置”，填写百度**通用文本翻译 API** 的 APPID 和密钥，选择目标语言后启用。此处不使用百度智能云的 API Key / Secret Key。
4. 配置页支持原文语言、多个目标语言、请求超时、调用间隔、自动发布开关。原文语言必须与现有数据一致，默认简体中文；已有译文后禁止直接切换。密钥不回显，留空保留旧密钥，不能通过普通站点配置接口读取。
5. 首次可执行 `php think i18n:translate --scan-only`，只扫描、不调用收费 API。在译文管理确认任务范围后，执行 `php think i18n:translate --limit=20`。
6. 在服务器已有调度系统中每分钟执行上述命令，按内容量调整 limit。默认每次调用间隔 1100 毫秒，失败会延迟重试，最多三次；三次失败后在后台手动重新翻译。任务执行期间的重复命令会退出。

本次代码变更不自动安装数据库、不启动定时任务、不调用真实百度接口。上线必须先执行初始化，再启用新代码的业务访问。PHP 需要 PDO MySQL、mbstring 和 DOM 扩展。

## 请求与响应

延用现有语言中间件：`?lang=en` 或 `think-lang: en`，也支持已有语言 Cookie 和浏览器语言检测。语言标识以 `config/i18n.php` 为准；如日语使用 `ja`，映射到百度的 `jp`。

示例：`GET /api/v1/projects?lang=ja`、`GET /api/v1/contents/detail?id=1&lang=en`。在后台启用相应目标语言后，返回结构保持原样，展示字段替换为该语言已发布译文；无译文、待审核或原文哈希不一致时回退原文。地区沿用既有中英文字段，其他语言仍回退中文。

现有部署若在反向代理/CDN缓存 API，请将语言参数、语言请求头和语言 Cookie 纳入缓存区分条件，避免不同用户语言相互覆盖。

## 覆盖范围

- 项目：名称、副标题、简介、正文，以及推荐卡片、推广位中的项目与分类名称。
- 资讯：标题、摘要、正文。作者自己的内容编辑列表保留原文，避免将译文误提交为原文。
- 分类：名称、描述及分类树。
- 订阅套餐、推广包：名称。
- 项目资料：审核通过的资料标题；文件本身不翻译。
- 里程碑：标题、标签、摘要、正文。
- v1 API 提示：`config/i18n_messages.php` 中的业务提示及现有 API 中文语言包。新增提示需要登记目录；带变量的提示使用 `TranslationService::formatMessage()`，如 `已生成 {count} 条推荐`。未登记的运行时异常详情回退原文。

项目、资讯关键词搜索同时查询原文和当前语言的已发布译文。搜索仍受原有发布状态、权限、软删除条件约束；源文本哈希不一致的译文不参与搜索。搜索采用 MySQL `SHA2()` 校验原文版本。大数据量场景应另建按语言分区的全文索引。

后台界面本身沿用原有语言包，本功能提供后台翻译配置和内容译文维护，不会把后台所有页面文案交给百度翻译。聊天、昵称、审核意见、账单、金额、状态、标识、链接不自动翻译。

## 翻译与修订规则

worker 定时扫描已发布内容，按“资源 + 记录 + 字段 + 目标语言”创建唯一任务。原文内容不变时不重复调用 API。只读取数据库译文的普通 API 请求不会触发百度翻译。

关闭自动发布时，机器译文进入待审核状态；打开后仅后续任务自动发布，已有待审核译文仍需人工处理。在译文管理中筛选“待审核”，勾选多条译文后点击“审核通过”，确认后批量发布。任一所选记录已过期、原文未发布、状态不符或译文为空时整批不发布，并提示对应译文 ID；审核不会改变译文内容或来源，也不会解除人工锁定。新增“批量审核发布”权限节点可通过重新执行 `php database/init_i18n.php` 注册，再按需分配给管理员角色。后台编辑译文后保存即锁定为人工版本，机器任务及其迟到结果都不能覆盖它。原文修改后立即回退原文，下次扫描标记人工译文为过期，人工刷新并重新修订后才能发布。

每个字段保存原文 SHA-256，worker 在调用前后检查原文，后台提交也检查当前版本。已删除或未发布的资源不会生成新任务。历史译文保留用于修订；不再通过业务 API 公开展示。

长文本按 UTF-8 字节切分；富文本通过 DOM 仅翻译文本节点，保留标签、属性和链接，跳过 script/style/code/pre。常见 `{{variable}}`、`{variable}` 和 printf 占位符保持不变。复杂前端模板或非标准 HTML 应先人工检查机器结果。

## 扩展和运维

- 增加语言：在 `config/i18n.php` 的 languages 添加应用语言标识、名称和百度代码，再在后台勾选目标语言。
- 增加数据库内容：在同一配置的 resources 注册受信任表名、允许翻译字段和发布条件，在对应读取接口显式调用 TranslationService，不能递归猜测任意响应字段。
- 私有配置保存在 app_i18n_setting；译文与任务保存在 app_translation；API 提示原文在 app_i18n_message。数据库备份需按包含凭据的数据管理。
- 当前 worker 使用本机文件锁。多服务器部署仅安排一个节点执行翻译调度，保证扫描去重和账户 QPS；若需多节点处理，需另行加入分布式锁和账户级限流。
- 命令显示成功/失败数，失败原因可在译文列表筛选查看。百度错误只记录错误码，不记录 HTTP 请求正文、签名和密钥。

百度接口文档：https://fanyi-api.baidu.com/doc_bd/21

## 验证

执行 `php tests/i18n_test.php`。测试使用内存 SQLite 和 Guzzle 模拟响应，不连接现有数据库或调用百度。验证签名、长文本、富文本、占位符、原文回退、人工锁定、失败处理、扫描和 worker 流程。真实百度账户权限、QPS、额度以及完整后台浏览器交互需在部署环境验证。
